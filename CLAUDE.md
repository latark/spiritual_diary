## 3. Соглашения по коду

- **TypeScript strict.** Никаких `any` — если нужен escape hatch, `unknown` + type guard.
- **Server Components по умолчанию.** Client component только когда нужен (`'use client'` на самом узком уровне).
- **Файлы:** kebab-case для папок, PascalCase для React-компонентов в файлах. Один компонент — один файл.
- **Экспорты:** named exports по умолчанию. Default только для page/layout (требование Next.js).
- **Папка компонента:** `MyComponent/index.tsx + MyComponent/MyComponent.tsx + MyComponent/types.ts` если сложный. Для простых — один файл.
- **Хуки:** `useFeatureName` всегда с `use`-префиксом, в файлах `useFeatureName.ts`.
- **Стили:** только Tailwind. CSS-модули и styled-components не используем. Если совсем нужно custom — CSS variables в `globals.css`.
- **shadcn:** компоненты ставим через MCP (`shadcn` server в `.mcp.json`), сразу в `src/shared/ui/`. Кастомизируем под нашу палитру.
- **Названия переменных** — на английском, всегда. Тексты для UI — только в локализационных файлах (`messages/ru.json` для русского).
- **Никаких комментариев в духе «// получаем данные»**. Комментарии только когда объясняют **зачем**, а не **что**.
- **Серверная логика** — в Edge Functions Supabase или в Next.js route handlers, никогда напрямую с клиента к секретным API.

**Шрифты:**
- Display/серифные акценты: **Cormorant Garamond** или **Playfair Display**
- UI: **Inter**
- Оба с кириллицей. Подключать через `next/font`.

**Анимации (обязательные принципы):**
- Длительность 300–500ms по умолчанию. Это медленный продукт.
- Никаких bounce/elastic кроме намеренных мест (флип карты дня — `easeOutBack` 800ms).
- Появление контента — fade + slight slide-up (8px), не резко.
- Дыхательный ритм 5-5 (вдох 5 сек / выдох 5 сек) — на это завязаны несколько анимаций (главная кнопка пульсирует в этом ритме, дыхательная практика).

**6 железных принципов:**
1. Темнота — норма (дефолт dark theme)
2. Минимум текста (иконка/анимация лучше слова)
3. Свечение вместо рамок (для hover/focus/selected)
4. Округлено всё (border-radius ≥ 12px, на крупных 20-24px)
5. Анимации медленные (300-500ms)
6. **Никаких прогресс-баров с %, бейджей "achievement unlocked", счётчиков очков.** Только метафоры свечения, дыхания, тотема.

Аудитория уязвимая. Любой text input от пользователя (мысль, ситуация, ответ на эмоцию дня, голосовая транскрипция) проходит через детектор крайних состояний:

1. Keyword list (RU + EN) — быстрый слой
2. LLM-классификатор — глубокий слой

При срабатывании:
- ИИ-анализ заменяется на safe-template с контактами поддержки
- Запись в `crisis_flags` для куратора школы (НЕ для контроля юзера — для своевременной поддержки человеком)
- В UI — отдельный экран с «ты не одна» + контакты

Telegram-алерт куратору при флаге. Эту логику **нельзя выключать или ослаблять** даже для тестов.

### RLS
Каждая таблица с пользовательскими данными — с включённым RLS. Без исключений. См. примеры политик в `spiritual_diary_spec.md` §4.4.

## 7. ИИ-слой

### Еженедельный анализ
- Запускается через pg_cron, обрабатывается Edge Function
- Контекст: все записи юзера за 7 дней + базовая вибрация + тотем + предыдущий анализ
- Модель: Claude Sonnet (последняя стабильная). Haiku — только для лёгких задач (генерация дневных карт пачкой)
- Output schema через Zod, retry on validation fail (1 раз)
- Стоимость трекать в `weekly_analyses.cost_usd` — это будущая боль unit economics
- Если записей < 4 за неделю → status `skipped_low_data`, юзеру мягкое уведомление

### Промпт-инженерия
- System prompt лежит в `supabase/functions/weekly-analysis/prompts/` с версионированием (v1.md, v2.md, ...)
- Никогда не хардкодим промпт в коде функции
- Никогда не отправляем в API PII (имена, локации) — обезличиваем перед отправкой
- В MVP — один общий тон голоса, не 4 тотема. Тотем в профиле есть, но в промпте используется упрощённо.

### Crisis check
ВСЕГДА перед публикацией ИИ-ответа юзеру:
1. Текст ответа прошёл через output filter (нет медицинских claim'ов, нет диагнозов)
2. Текст пользовательского ввода прошёл через crisis detector

Если crisis flag — ИИ-ответ заменяется на safe-template целиком.

## 12. Стиль работы с Артёмом

- **Русский язык.** В коде — английский (комментарии, имена). В чате — русский.
- **Опытный собеседник.** Без объяснений базовых концептов (что такое RLS, что такое FSD, что такое RSC), без вступлений «отличный вопрос». Сразу по делу.
- **Filesystem доступен** — пиши прямо в файлы проекта, не копируй код в чат. Артём не хочет копипастить. Исключение — когда обсуждаем подход или быстрый сниппет.
- **osascript доступен** — можно запускать `git`, `npm`, `npx`, тесты прямо в проекте.
- **Не спрашивай разрешений на каждый шаг.** Если решение очевидное (создать папку, поставить очевидную зависимость, написать миграцию) — делай, потом покажи. Если решение влияет на архитектуру или есть несколько разумных путей — обсуди.
- **Меняй мнение, если есть аргументы.** Артём аргументирует — будь готов признать. Не упрямься ради консистентности.
- **Считай сроки реалистично, но с учётом вайбкодинга.** Artem делает многое за 1 день с Клодом, что в традиционной оценке заняло бы неделю. Не закладывай старые мерки.
- **Никаких приукрашиваний.** «Готово, но...» лучше чем «успешно сделано».
- **Декомпозируй большие задачи.** Не пытайся сделать всё в одном tool-call'е.
